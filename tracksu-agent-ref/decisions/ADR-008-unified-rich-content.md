# ADR-008: единый конвейер rich-контента и Markdown — `markdown`

2026-10-08 · принято (запрос пользователя: «хорошая поддержка компонентов
Markdown… в профилях многие юзают маркдаун… унифицированно,
консолидированно»).

## Контекст

osu! присылает форматированный текст в трёх видах: HTML, отрисованный
сервером (новости, «О себе», описания карт, комментарии, changelog), сырой
BBCode (описания команд) и Markdown (wiki, исходники новостей). Игроки в
«О себе» часто пишут Markdown (`**жирный**`, `# Заголовок`, `- пункт`), но
osu! рендерит BBCode и показывает это как текст — и на сайте, и у нас.

## Решение

Один путь для всех форматов:

```
формат-адаптер → HTML → ContentNormalizer (allowlist) → ContentDocument → ContentFrame
```

- `ContentParser.parse(source, format: html|bbcode|markdown, base,
  markdownInText)` — единственная точка входа (`_shared/content/data/`).
  Новости, профили и команды переведены на него; wiki будет на нём же.
- Markdown → HTML: пакет `markdown` (dart-lang, BSD-3, без нативного кода),
  GitHub-flavoured (таблицы, списки, код, зачёркивание, автоссылки).
  YAML front matter и контейнеры wiki `:::` отбрасываются.
- Markdown внутри отрисованного HTML (`markdownInText`, сейчас — «О себе»):
  строки делятся по `<br>`; в начале строки `#`…`######` → заголовок,
  `>` → цитата, `-`/`*`/`+` и `1.` → списки (соседние строки — один список),
  `---` → линия; внутри строк — жирный, курсив, код, зачёркивание, ссылки.
  Текст внутри ссылок, `code` и `pre` не трогается. Без признаков Markdown
  HTML возвращается без изменений (дешёвая проверка перед разбором).
- Безопасность не меняется: любой результат адаптера проходит тот же
  allowlist тегов, лимиты размера/узлов/картинок и `PublicWebLink`; сырой HTML
  внутри Markdown тоже фильтруется. Скрипты, стили и чужие плееры не
  исполняются.

## Последствия

- Новый формат подключается адаптером в `ContentParser`, без второго
  рендерера и без изменений в UI.
- Changelog-записи и комментарии пока рисуются `HtmlWidget` напрямую
  (короткие фрагменты без медиа); перевод на `ContentFrame` — при следующей
  доработке этих экранов, если понадобятся картинки/спойлеры.
- Эвристика Markdown в «О себе» может оформить текст, который автор не имел
  в виду как Markdown (например, строка, начинающаяся с `- `). Принято: это
  совпадает с тем, как такие тексты обычно задуманы.
- `pubspec.lock`: `markdown 7.3.1` разрешился при сборке Xcode
  (`flutter assemble` выполнил pub get).
