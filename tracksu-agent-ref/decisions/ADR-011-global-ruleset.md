# ADR-011: один режим игры в шапке

2026-10-09 · принято (решение пользователя: режим выбирать один раз и носить
по страницам; чужой профиль — в основном режиме игрока).

## Контекст

Переключатель режимов (osu! / taiko / catch / mania) стоял полной строкой
почти на каждой значимой странице — профиль, рейтинги, команда, Spotlights —
и забирал 10–20 % высоты контента. Выбор приходилось повторять на каждой
странице.

## Решение

- Один режим на всё приложение: `RulesetController` (ValueNotifier,
  хранится как тема, `FlutterSecureRulesetStore`, ключ `app_ruleset`).
- В шапке — `RulesetButton`: иконка режима, тап открывает шторку из четырёх
  строк (`UiModal.selection`, иконки через `UiChoice.leading`). Стоит первой
  в `AppBarActions(ruleset:)`: режим · поделиться · аккаунт. Это исключение
  из «двух действий» ADR-010 только для страниц, показанных по режиму.
- Глобальный режим ведут рейтинги (игроки, команды, страны; на Kudosu
  кнопки нет — там нет режима) и Spotlights: стартуют в нём и
  перезагружаются при смене (`RulesetListener`).
- Профиль и команда — страницы «чьи-то»: открываются в основном режиме
  игрока/команды (или в режиме страницы, откуда пришли, например из
  рейтинга mania), кнопка в шапке у них локальная и меняет только эту
  страницу, общий выбор не трогает.
- Карта, поиск карт и страница карты остаются со своими фильтрами: режим
  там — свойство конкретной карты или запроса, а не настройка просмотра.

## Последствия

- Строки `OsuRulesetSelector` убраны со страниц; виджет остаётся для
  каталога и как источник подписей (`OsuRulesetSelector.label`).
- `RankingsStarted(type:)`, `SpotlightsBloc(ruleset:)` принимают стартовый
  режим, чтобы не делать лишний запрос в osu! перед переключением.
- Сохранение режима — best-effort: при ошибке записи выбор действует до
  конца сессии.
