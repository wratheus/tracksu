# ADR-009: ссылки внутри приложения и просмотр одной страницы — `webview_flutter`

2026-10-08 · принято (запрос пользователя: «чтобы до нас потом не доебались,
что открывается вебвью и можно переходить куда хочешь по сайтам… нужно чисто
как страничку открывать»).

## Контекст

Ссылки из новостей, профилей, комментариев, changelog, wiki и команд раньше
открывались через `url_launcher` в `inAppBrowserView`
(SFSafariViewController / Custom Tabs). Это полноценный браузер: адресная
строка, переходы по любым сайтам. Для ревью магазинов приложение не должно
выглядеть как браузер общего назначения, а ссылки на сам osu! должны вести
на наши экраны.

## Решение

Одна точка входа — `AppLinks.open(context, uri)` (`_shared/navigation/`):

1. `osu.ppy.sh` / `ppy.sh`:
   - `/wiki/…` → экран wiki (`openWiki`);
   - `/users|u/{id|имя}[/режим]` → профиль; без режима — режим по умолчанию
     игрока (`ProfileParams.defaultMode`, один запрос `/users/{id}`);
   - `/beatmapsets|s/{id}#режим/{bid}`, `/beatmaps|b/{id}` → карта;
   - `/teams/{id}` → команда.
2. YouTube и всё, что не `https`, → системный браузер
   (`ExternalLinks.openInBrowser`, `LaunchMode.externalApplication`).
3. Остальное → `WebPageScreen` (route `…/web?url=`): одна страница в
   `webview_flutter`.

Правила `WebPageScreen`:

- Нет адресной строки и поля ввода: в шапке заголовок страницы и хост,
  «Поделиться» (`ShareTarget.webPage`, только https), линия прогресса.
- Пока страница грузится, разрешены редиректы (https). После первого
  `onPageFinished` разрешена только та же страница (без учёта `#якоря`);
  любая другая навигация в основном фрейме отменяется и уходит в системный
  браузер. Подфреймы (встроенные плееры) не ограничиваются.
- Не-https переходы запрещены всегда. Route принимает только `https` без
  `userinfo`, URL ≤ 4096 символов.
- Ошибка загрузки → сообщение и кнопка «Открыть в браузере».

## Альтернативы

- Оставить `inAppBrowserView` — свободная навигация, именно её и убираем.
- Всё в системный браузер — выкидывает из приложения ради каждой статьи
  новостей; оставлено как выход для «чужих» переходов.
- Свой рендер внешних страниц — невозможен в общем виде.

## Последствия

- Новая прямая зависимость `webview_flutter` (flutter.dev, BSD-3; WKWebView /
  Android WebView). `url_launcher` остаётся для системного браузера.
- Новые места со ссылками обязаны вызывать `AppLinks.open`, а не
  `launchUrl`; `ExternalLinks.openInBrowser` — только для явного «Открыть в
  браузере».
- JavaScript на странице включён (иначе большинство сайтов не работает);
  страница не получает токены и cookie приложения.
