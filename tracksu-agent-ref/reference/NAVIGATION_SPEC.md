# P07.2 — мобильная навигация и stateful shell

Статус: требования согласованы по направлению, архитектура и спорные UX-решения
согласуются перед реализацией. Код сейчас не меняем. Android первым; iOS
закладываем в контракт, проверяем после возвращения host в P04.

## Цель и исходное состояние

Вернуть постоянную нижнюю навигацию, независимые стеки основных разделов,
сохранение состояния и платформенное поведение Back. Удаление старого HomePage
и curved_navigation_bar не означает отказ от этой возможности. Текущий
GuestShell с переходами из AppBar — промежуточное решение.

Предлагаемые вкладки: Поиск / Рейтинги / Новости; старт — Поиск в гостевом режиме.
Аккаунт/настройки доступны отдельно. Результаты и карты принадлежат профилю,
не являются глобальными вкладками без выбранного игрока.

## Архитектурное решение

- Сравнить текущий TracksuAppRouter + вложенные Navigator с декларативным
  Router/go_router + StatefulShellRoute. Bottom bar сам по себе не требует
  нового пакета; важны корректные стеки, deep links, restoration и Back.
- Предпочитать поддерживаемые Flutter API и стандартные page transitions.
  Не возвращать curved_navigation_bar и не писать свой gesture recognizer
  вместо платформенного механизма маршрутов.
- До зависимости/миграции оформить ADR: выбранный вариант, версия и совместимость
  с закреплённым SDK, ownership root/branch Navigator, ключи маршрутов,
  обработка callback и порядок переноса. Выбор согласовать с пользователем.
- Сохранить typed navigation facade. Фичи не знают строк маршрутов других фич,
  не получают BuildContext в repository/Bloc; переходы через UI side effects.
- У каждой вкладки собственный стек. Детали игрока, карты и статьи открываются
  в текущей ветке: профиль из рейтинга возвращает в тот же рейтинг, а не в Поиск.
- Root Navigator — для действительно общих поверхностей, например OAuth
  и глобальных модалок. Не отправлять все детали поверх root по привычке.
- Согласовать на макетах видимость bottom bar на detail routes; рекомендуем
  сохранять его на обычных деталях, скрывать на OAuth/full-screen modal.

## Контракт Back и жестов

1. При открытом меню/диалоге/sheet Back закрывает верхнюю dismissible поверхность.
   Системная клавиатура обрабатывается платформенно; не делать одновременно
   dismiss клавиатуры и неожиданный pop страницы.
2. Затем Back снимает верхний route активной ветки. Не проверять только
   rootNavigator.canPop: это может пропустить историю внутри вкладки.
3. На корне неосновной вкладки предлагается Android Back → сохранённая ветка
   Поиска; не очищать её стек. Не строить бесконечную историю переключений вкладок.
   Это продуктовая политика, а не автоматическое поведение Flutter;
   подтвердить перед реализацией, в том числе корректность predictive preview.
4. Только когда доступных внутренних шагов больше нет, на стартовом корне
   Android Back может вернуть пользователя в ОС. Не вызывать exit/SystemNavigator.pop
   вместо нормальной навигации и не блокировать выход навсегда.
5. На корне iOS нет искусственного swipe-to-exit или жеста Back между вкладками.

### iOS

Использовать интерактивный Cupertino-style edge swipe для push/pop маршрутов:
экран следует за пальцем, жест можно завершить или отменить. Отмена не теряет
данные и не запускает повторный запрос. Не заменять переход fade-анимацией,
которая лишь похожа на навигацию, но не поддерживает интерактивный pop.
Не отключать жест глобальным canPop:false. Блокировки применять лишь при
реальной необходимости, с понятным сценарием выхода.

### Android

Поддержать системный Back: кнопку и edge gesture, включая predictive back
на поддерживаемых версиях ОС/SDK. Это не просто произвольно выбранный fade.
Использовать платформенные transitions текущего Flutter, проверить направление
и destination preview в nested Navigator, завершение и отмену жеста.
PopScope/NavigatorPopHandler применять по назначению; не возвращать WillPopScope
и не делать поздний асинхронный перехват каждого жеста. Нельзя делать второй pop
после уже успешного pop или уходить из приложения при непустом стеке ветки.

## Состояние и lifecycle

- Переключение вкладки возвращает на оставленный экран со scroll offset,
  поиском, фильтрами, ruleset, выбранной категорией/сложностью и пагинацией.
- Повторное нажатие текущей вкладки по умолчанию ничего не сбрасывает.
  Pop-to-root/scroll-to-top — отдельный явно согласованный UX, не скрытый побочный эффект.
- Не пересоздавать Bloc/repository/controller всей ветки на каждом tap.
  Не запускать повторные fetch лишь из-за переключения вкладки или rebuild shell.
- Сохранённая ветка не обязана активно работать в фоне: приостановить ненужные
  таймеры/анимации/подписки по visibility, отменять запросы при действительном
  уничтожении owner. Не прогружать все страницы всех вкладок заранее.
- Смена языка/темы не очищает стеки и результаты. Refresh имеет отдельную
  политику актуальности, а не маскируется под пересоздание экрана.
- Login/cancel/error возвращает в исходный контекст. Успех не должен без причины
  очищать весь shell. Logout/смена аккаунта удаляет приватный state прежнего
  пользователя, сохраняя безопасный публичный контекст; запретить stale responses.

## Deep links, callback и восстановление

- Разделить сохранение в памяти при tab switching и восстановление после
  уничтожения процесса: это разные задачи, IndexedStack не решает вторую.
- Определить минимальный restoration scope: активная вкладка, сериализуемые
  route IDs/params, фильтры и позиции. API-данные перезагружаются по необходимости;
  не обещать восстановление всего кэша и гарантии после force-stop.
- Не сохранять OAuth code/state, access/refresh token в route restoration,
  URL-логах или аналитике. Сессия принадлежит существующему secure storage.
- Холодный/тёплый callback обрабатывается однократно без дублирования shell,
  браузера и страниц. Возврат из браузера не считать успехом без результата OAuth.
- Для ссылок на сущности подготовить контракт: найти корректную ветку,
  построить предсказуемый back stack, показать ошибку для неверного ID.
  Поддержка новых публичных deep links не подразумевается без отдельного scope.

## План реализации и критерии

1. ADR и согласование Back-at-tab-root, структуры вкладок, видимости панели
   и границ restoration; схема экранов от Stitch.
2. Цельный shell + стеки + перенос существующих переходов, без новых функций
   и без обязательного ожидания финальных цветов. Отдельный связный коммит.
3. OAuth/links/restoration и lifecycle; отдельный связный коммит при необходимости.
4. Платформенные проверки и исправления; оформление из UI kit после согласования.

Функциональный shell можно делать до полного редизайна после согласования ADR.
Не сливать его с переписыванием API/всех экранов. Поддерживать ROADMAP и handoff.
Автотесты сейчас не писать и не запускать; format/analyze/build по scope,
поведение вручную проверяет пользователь.

Ручной checklist:

- Поиск → профиль → карта → другая вкладка → назад к Поиску: тот же route и scroll.
- Рейтинг со страной/mania variant → профиль → карта → Back два раза:
  тот же рейтинг, фильтры, страница и позиция.
- Новости → статья → другая вкладка → Новости: та же статья; Back → прежняя лента.
- Sheet/клавиатура/Back не снимают лишнюю страницу; быстрые taps не дублируют route.
- Android gesture/button Back и отменённый predictive gesture; последний
  root выходит штатно, непустая ветка никогда не закрывает приложение.
- iOS завершённый/отменённый edge swipe и модалки — отдельно после P04.
- OAuth success/cancel/error, браузер с активной сессией, cold callback,
  logout/смена аккаунта без утечки чужого состояния.
- Смена языка/темы, background/resume и восстановление после process death
  в рамках согласованного restoration scope.
