# P48 — общий AppBar и единый поиск

2026-10-07 · направление выбрано пользователем; следующий этап после P44–P47.
Статус: in_progress. База: 86669fa, рабочее дерево чистое.
План коммитов: единый поиск и AppBar; затем проверки, отладка и документация.
Ответственность: Main создаёт source/repository/Bloc; Bloc владеет запросами,
отменой и cache; экран — вводом, debounce и навигацией; UI kit — шапкой.

## Принято

- Единый поиск с вкладками «Игроки / Карты» (явный выбор пользователя).
- Убрать предварительный выбор ruleset из поиска игрока: ищем аккаунт,
  режим статистики переключаем в профиле.
- Переработать общую шапку и её вкладки через один компонент UI kit.
- Компактный вход вместо большой формы «Найти игрока»; подсказки после
  паузы ввода. Поле поиска располагается в AppBar поискового экрана.

## Реализованный срез

1. Общий AppBar: заголовок/назад, действия, тонкая индикация загрузки,
   слот связанных со страницами вкладок. Действия шапки должны учитывать
   активную вкладку: сейчас ShareTarget в рейтингах всегда собирается по
   Players, даже на Teams/Countries/Kudosu; исправить в этом срезе. Сначала поисковый экран;
   затем рейтинги/профиль без изменения их навигации и scroll ownership.
2. Один route поиска, одна строка ввода, «Игроки / Карты» под ней.
   Вкладка карт сохраняет существующие фильтры и пагинацию.
3. Debounce 400 ms, от двух символов; Enter запускает сразу.
   Latest-query-wins, отмена старого запроса, краткий cache, дедупликация
   одинакового запроса, обработка 429 без немедленного повторения.
   Пустая строка не запускает сетевой поиск. Не отправляем оба поиска на
   каждый символ: только активная вкладка. Сохраняем ввод при переключении.
4. Игроки: компактные строки avatar/ник/страна → профиль. Точный ID и
   @числовой-ник сохраняются как отдельный однозначный lookup.
   Режим первого открытия — основной режим игрока из API;
   fallback osu при отсутствии данных. Compact user не содержит playmode,
   поэтому перед открытием выполняется GET /users/{id} без режима; «пустая статистика» не равна
   «игрока не существует».
5. Карты: короткие результаты с обложкой/названием/автором; переход в
   существующую страницу набора. Сохраняем её difficulty selection.

## API-основания

- [Search API](https://osu.ppy.sh/docs/index.html#search): public scope,
  `/search?mode=user&query=…`, `user.data`/`user.total`, до 100 результатов.
- [SearchParams](https://github.com/ppy/osu-web/blob/master/app/Libraries/Elasticsearch/SearchParams.php):
  `shouldReturnEmptyResponse` проверяет отсутствие и пользователя, и OAuth token.
  `isLoginRequired` в UserSearchRequestParams само по себе не означает
  запрет client-credentials API. Не путать с website quickSearch.
- Карты: уже используемый `/beatmapsets/search`, guest-доступ проверяется
  в P45. Подсказки — представление результатов поиска, отдельный suggestion
  endpoint не нужен.
- Не обещаем полноту поиска, наличие статистики во всех режимах или
  выдачу за пределами серверных ограничений.

2026-10-07: live API с client-credentials/public token, без пользовательской
сессии: `/search?mode=user&query=peppy` → одна строка, total=1. Гостевые
подсказки доступны. Значения credentials/token не сохранялись в отчёт.

## Критерии проверки

Быстрый ввод A→B не показывает A после ответа B; смена вкладки сохраняет текст;
закрытие во время запроса безопасно; guest поиск работает; Enter/clear/back,
клавиатура, светлая/тёмная темы, длинные подписи и крупный шрифт; прежние
переходы из рейтингов/истории и повторный тап navbar сохраняются.

Scope не включает OAuth callback, iPad master-detail, локальное избранное,
историю пользователей, новые scopes или массовую перестройку всех экранов.

## Единые действия шапки (2026-10-08, запрос пользователя)

Проблема: на разных вкладках разный набор и порядок кнопок; вход в аккаунт
был только на главной. Решение — один компонент `AppBarActions`
(`lib/src/_shared/chrome/`), фиксированный порядок на всех экранах:
**поделиться · настройки · аккаунт**.

- `AccountButton` (бывш. `guest/AccountActions`): гость — «Войти через osu!»,
  авторизованный — профиль / другой аккаунт / выход. Пункт «Настройки» из
  меню убран: рядом всегда есть кнопка настроек.
- Аватар грузится один раз на смену сессии и делится всеми шапками
  (раньше — запрос `/me` на каждый экземпляр; теперь кнопка на каждой странице).
- Пока делиться нечем (загрузка), «Поделиться» видна, но неактивна — кнопки
  не сдвигаются.
- Экраны: главная, поиск, рейтинги, новости, профиль, медали, команда,
  спотлайты, карта, карта дня и её история. Настройки/логин/about — без них.
- Поиск: поле переехало из заголовка в нижний слот AppBar (полная ширина),
  заголовок «Поиск». Делится ссылкой на поиск сайта: игроки
  `/home/search?mode=user&query=`, карты `/beatmapsets?q=`.
- Карта дня делится комнатой `/multiplayer/rooms/{id}`, история —
  `/rankings/daily-challenge` (оба маршрута есть в osu-web `routes/web.php`).

Кнопки «Обновить» из шапок убраны (уточнение пользователя): обновление —
только pull-to-refresh. Его не было у медалей, команды и спотлайтов —
добавлен `RefreshIndicator` (повтор не отправляется, пока идёт обновление).

Также удалено пояснение под «Настройками модов» в подробностях результата
(«Названия параметров сохранены из API…») и ключ
`scoreModSettingsExplanation` во всех 7 ARB.

## Поиск игроков (2026-10-08, запрос пользователя)

- Поле поиска получает фокус при открытии экрана (`UiSearchField.autofocus`).
- Строка игрока — как остальные плитки: `UiSurface.card` + `OsuAvatarBands`,
  квадратный скруглённый аватар (`UiAvatar.row`), ник с сердцем supporter и
  точкой «в сети», под ним флаг страны и команды (`OsuPlayerFlags`).
  `SearchPlayer` получил `team`, `isOnline`, `isSupporter` из ответа
  `/search` (UserCompact: `team`, `is_online`, `is_supporter`).
- Переход к игроку больше не ждёт lookup режима: профиль открывается сразу
  (`ProfileParams.defaultMode`, route `…/users/{id}/default`), один запрос
  `GET /users/{id}` без режима отдаёт статистику режима игрока по умолчанию
  (`playmode`), Bloc берёт его как текущий ruleset.

## Стабильная шапка и своя кнопка «назад» (2026-10-09, запрос пользователя)

Проблема: при переходе «Рейтинги → профиль» заголовок и кнопки шапки
прыгали на несколько пунктов. Причина не в leading: нижние строки шапки
(«Рейтинги», вкладка «osu!») были выше объявленного `preferredSize` (66 при
фактических ~70: отступы 8 + 4, сегменты 60, линия прогресса 2). Material
`AppBar` в этом случае сжимает строку toolbar и сдвигает её элементы вверх;
у профиля высота совпадала, поэтому казалось, что сдвиг даёт «назад».

- `UiAppBar` отдаёт `bottom` ровно объявленную высоту (`_PinnedBottom`):
  toolbar больше никогда не сжимается, переполнение видно в debug.
- Высоты считаются, а не пишутся числами: `UiSegmentedControl.heightOf`
  (отступы, иконка, строка подписи с учётом масштаба текста),
  `UiSearchField.heightOf`, `UiAppBar.segmentedRowHeight`; одинаковый
  отступ строки вкладок `UiAppBar.rowPadding` — строки не смещаются между
  экранами (профиль раньше был без верхнего отступа).
- `UiBackButton`: компактная кнопка 36 pt в форме сегментов (скошенные углы,
  стекло), область нажатия 48 pt, край совпадает с отступом контента 16 pt;
  на fullscreen-диалогах — крестик. Свайп назад iOS и системный back не
  затронуты.
- Все экраны со стандартным `AppBar` переведены на `UiAppBar`: настройки,
  карта, вход, wiki, лицензии, «О приложении», страница по ссылке, карта дня
  и история, медали, новости, команда, спотлайты.

## Поиск в шапке (2026-10-09, запрос пользователя)

«Поиск чтобы всегда был из эппбаров всех, как раньше, но поумному,
современно» + оверфлоу 2 px на экране поиска (в высоту `bottom` не была
включена линия прогресса).

- `UiSearchPill` (kit, `app_bar_search.dart`): первая кнопка в
  `AppBarActions` на всех экранах — «🔍 Поиск» на корнях вкладок, только
  иконка на открытых страницах (длинным заголовкам хватает места). Форма —
  та же стеклянная со скосами, что у сегментов и «назад», 36 pt в цели 48.
- Экран поиска: поле `UiAppBarSearchField` встало на место заголовка
  (подсказка вместо плавающей метки, очистка), снизу только вкладки
  Игроки / Карты / Вики и линия прогресса; высота — через
  `UiAppBar.segmentedRowHeight` + `UiAppBarProgress.height`, оверфлоу ушёл.
- Общий hero (`UiAppBarSearch.heroTag`): пилюля перетекает в поле при
  открытии поиска; в полёте — только стеклянная форма, живое поле не летит.
- Порядок действий шапки: поиск · поделиться · настройки · аккаунт;
  на самом экране поиска пилюли нет (`AppBarActions(search: false)`).
- `UiSearchField.heightOf` удалён — поле больше не в `bottom`.

## Шапка по гайдлайнам iOS (2026-10-09, решение пользователя)

Скрины: шапка перегружена (назад + заголовок + пилюля + 3 кнопки).
Решение пользователя: «по гайдлайнам iOS, поиск внизу; три точки — если
необходимо; заголовки не делать большими». [ADR-010](../../decisions/ADR-010-ios-navigation.md).

- Шапка: ‹ · заголовок обычного размера · **поделиться · аккаунт** (не
  больше двух действий). Настройки — пункт меню аккаунта (последний, после
  разделителя), `SettingsButton` удалён. «⋯» не понадобилось: страничных
  действий сверх «поделиться» сейчас нет; появятся — уйдут в «⋯».
- Пилюля поиска в шапке и её hero убраны (`UiSearchPill`,
  `UiAppBarSearchField` → `UiSearchBar`).
- Нижняя панель (`UiNavigationBar`, своя): Главная / Рейтинги / osu! и
  отдельная круглая кнопка поиска справа — вкладка поиска iOS 26. Ветка
  `/find` — корень поиска; первая вкладка «Главная» осталась на `/search`
  ради старых ссылок. `ShellTab { home, rankings, news, find }`.
- Экран поиска: заголовок «Поиск», под шапкой Игроки / Карты / Вики, поле
  `UiSearchBar` внизу над клавиатурой; повторное нажатие вкладки — фокус в
  поле. `openSearch` и `…/beatmaps` переключают на вкладку поиска.
