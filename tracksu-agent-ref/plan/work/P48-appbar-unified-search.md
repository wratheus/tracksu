# P48 — общий AppBar и единый поиск

2026-10-07 · направление выбрано пользователем; следующий этап после P44–P47.
Реализация ещё не начата.

## Принято

- Единый поиск с вкладками «Игроки / Карты» (явный выбор пользователя).
- Убрать предварительный выбор ruleset из поиска игрока: ищем аккаунт,
  режим статистики переключаем в профиле.
- Переработать общую шапку и её вкладки через один компонент UI kit.
- Компактный вход вместо большой формы «Найти игрока»; подсказки после
  паузы ввода. Поле поиска располагается в AppBar поискового экрана.

## Предложенный срез

1. Общий AppBar: заголовок/назад, действия, тонкая индикация загрузки,
   слот связанных со страницами вкладок. Действия шапки должны учитывать
   активную вкладку: сейчас ShareTarget в рейтингах всегда собирается по
   Players, даже на Teams/Countries/Kudosu; исправить в этом срезе. Сначала поисковый экран;
   затем рейтинги/профиль без изменения их навигации и scroll ownership.
2. Один route поиска, одна строка ввода, «Игроки / Карты» под ней.
   Вкладка карт сохраняет существующие фильтры и пагинацию.
3. Debounce 400 ms, от двух символов; Enter запускает сразу.
   Latest-query-wins, отмена старого запроса, краткий cache, дедупликация
   одинакового запроса, обработка 429 без немедленного повторения.
   Пустая строка не запускает сетевой поиск. Не отправляем оба поиска на
   каждый символ: только активная вкладка. Сохраняем ввод при переключении.
4. Игроки: компактные строки avatar/ник/страна → профиль. Точный ID и
   @числовой-ник сохраняются как отдельный однозначный lookup.
   Предлагаемый режим первого открытия — основной режим игрока из API;
   fallback osu при отсутствии данных. Это ещё требует проверки контракта
   текущего ProfileParams и API ответа; «пустая статистика» не равна
   «игрока не существует».
5. Карты: короткие результаты с обложкой/названием/автором; переход в
   существующую страницу набора. Сохраняем её difficulty selection.

## API-основания

- [Search API](https://osu.ppy.sh/docs/index.html#search): public scope,
  `/search?mode=user&query=…`, `user.data`/`user.total`, до 100 результатов.
- [SearchParams](https://github.com/ppy/osu-web/blob/master/app/Libraries/Elasticsearch/SearchParams.php):
  `shouldReturnEmptyResponse` проверяет отсутствие и пользователя, и OAuth token.
  `isLoginRequired` в UserSearchRequestParams само по себе не означает
  запрет client-credentials API. Не путать с website quickSearch.
- Карты: уже используемый `/beatmapsets/search`, guest-доступ проверяется
  в P45. Подсказки — представление результатов поиска, отдельный suggestion
  endpoint не нужен.
- Не обещаем полноту поиска, наличие статистики во всех режимах или
  выдачу за пределами серверных ограничений.

## Критерии будущей проверки

Быстрый ввод A→B не показывает A после ответа B; смена вкладки сохраняет текст;
закрытие во время запроса безопасно; guest поиск работает; Enter/clear/back,
клавиатура, светлая/тёмная темы, длинные подписи и крупный шрифт; прежние
переходы из рейтингов/истории и повторный тап navbar сохраняются.

Scope не включает OAuth callback, iPad master-detail, локальное избранное,
историю пользователей, новые scopes или массовую перестройку всех экранов.
