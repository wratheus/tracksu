## API (osu-web, срез 04643de)

- `GET /forums` — разделы верхнего уровня с подразделами (2 уровня),
  фильтр `ForumView`; scope public. `Forum`: `id`, `name`, `description`.
- `GET /forums/{id}` — раздел, `subforums.subforums`, `pinned_topics` и
  первые 50 обычных тем (без курсора).
- `GET /forums/topics?forum_id=&sort=new&limit=50&cursor_string=` — темы по
  времени последнего поста, курсор; закреплённые темы тоже приходят, по дате.
- `GET /forums/topics/{id}?sort=id_asc&limit=20&cursor_string=` — тема и
  посты (`body.html` — уже отрисованный BBCode). Курсор приходит после
  любой непустой страницы; конец темы — страница короче `limit`.
- У постов и тем только `user_id`: авторы — `GET /users?ids[]=…` (до 50,
  scope public). Для этого `HttpRestClient` теперь передаёт список как
  повтор ключа (`ids[]=1&ids[]=2`).
- Allowlist гостевого клиента: `^/api/v2/forums(/id|/topics(/id)?)?$` и
  `/api/v2/users`. Ответ/новая тема требуют `forum.write` и входа — после P37.

## Поведение

- Вкладка «osu!»: Новости / События / **Форум** / Изменения. Форум —
  группы разделов, строки подразделов с описанием; кэш на сессию.
- Раздел (`…/forums/{id}`): описание, подразделы, закреплённые темы
  (объявления, закреплено, закрыто) сверху, затем темы по последнему посту;
  подгрузка в конце, не чаще страницы в секунду. Первый экран — из двух
  параллельных запросов; закреплённые темы не дублируются в списке.
- Тема (`…/topic/{id}`): заголовок, ответы и просмотры; посты по порядку в
  общем ридере контента (цитаты, спойлеры, картинки по настройке медиа,
  ссылки через `AppLinks`), автор — аватар и ник, тап открывает профиль в
  режиме игрока по умолчанию; «изменено». Пост, который не удалось
  разобрать, — сообщение и «Открыть оригинал».
- Ссылки `osu.ppy.sh/community/forums/{id}`, `/community/forums/topics/{id}`,
  `/forum/{id}`, `/forum/t/{id}` открываются в приложении.
- «Поделиться»: форум, раздел, тема на сайте.
