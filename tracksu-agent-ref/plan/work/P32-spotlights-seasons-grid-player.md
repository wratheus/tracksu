# P32 — Spotlights и Seasons: решения; сетка карточек; плеер

2026-10-03 · сетка, плеер и доработки реализованы в коде (awaiting_manual_check);
решения по Spotlights/Seasons приняты (раздел «Принятые решения»).

## Коротко

- **Spotlights устарели.** Последняя подборка — «Seasonal Spotlights:
  Winter 2020» (09.04–25.06.2020). На сайте раздел называется
  «Spotlights (old)». Новых подборок нет; API по-прежнему отдаёт архив
  2013–2020 годов.
- **Seasons через публичный API полноценно сделать нельзя.** Страница сезона
  `osu.ppy.sh/seasons/{id}` отдаёт только HTML. В API v2 нет списка сезонов,
  общего сезонного рейтинга и дивизионов. Есть только комнаты-плейлисты
  сезона по известному id.
- **Чем заменить.** Актуальные и доступные через API разделы —
  **рейтинг команд** и **Daily challenge**.

## Что сейчас есть в рейтингах osu! и что доступно в API

Проверено 2026-10-03 по сайту и исходникам ppy/osu-web (`routes/web.php`,
`RankingController`, `SpotlightsController`, `SeasonsController`,
`Multiplayer\RoomsController`, `Models\Season`, `Models\Multiplayer\Room`).
API — v2 с client credentials и scope `public`, как сейчас в приложении.

| Раздел на сайте | Что это | Публичный API v2 | В приложении | Вывод |
| --- | --- | --- | --- | --- |
| Global (PP / score) | Мировой рейтинг игроков | `GET /rankings/{mode}/performance\|score` | есть | — |
| Country | Рейтинг **стран** (суммарно по стране) | `GET /rankings/{mode}/country` | нет | можно сделать, ценность средняя |
| Team | Рейтинг **команд** | `GET /rankings/{mode}/team` — работает в коде сервера, **не в документации** | нет (сами команды есть) | можно, с оговоркой о контракте |
| Spotlights (old) | Архив чартов 2013–2020 | `GET /spotlights`, `GET /rankings/{mode}/charts` | есть (P31) | работает, но это архив |
| Playlists → Seasons | Сезоны плейлистов с дивизионами и общим счётом | Только `GET /rooms?season_id={id}&mode=all` и `GET /rooms/{room}/leaderboard`. Нет списка сезонов, общего рейтинга и дивизионов | нет | полноценно — нельзя, только частично |
| Playlists → Featured | Плейлисты Featured Artist | `GET /rooms?category=featured_artist` | нет | возможно, ценность низкая |
| Daily challenge | Карта дня, рейтинг дня, серии игрока | `GET /rooms?category=daily_challenge` (комнаты отдаются с `x-api-version` ≥ 20240529), `GET /rooms/{room}/leaderboard`; статистика игрока — в профиле | нет | можно, сначала проверить живой API |
| Top plays, Ranked play | Лучшие скоры, матчмейкинг | в `rankings/{mode}/{type}` API принимает только `charts`, `country`, `global`, `team` | нет | через API нельзя |
| Kudosu | Рейтинг помощи с картами | `GET /rankings/kudosu` | нет | нишево |

**Официальная документация** ([osu.ppy.sh/docs](https://osu.ppy.sh/docs/index.html),
генерируется из docblocks osu-web) — источник контракта. Что в ней есть:

- `RankingType` документирован только как `charts` (Spotlight), `country`,
  `performance`, `score` (`resources/views/docs/_structures/ranking_type.md`).
  **`team` сервер принимает, но в документации его нет** — это
  недокументированный контракт, он может измениться без версии API.
- «Get Multiplayer Rooms» (`GET /rooms`) документирован: `limit`, `mode`
  (`active`, `all`, `ended`, `participated`, `owned`), `season_id`, `sort`,
  `type_group`, scope `public`. Параметр `category` в документации отдельно
  не описан — упомянут только в таблице `x-api-version` (комнаты
  `daily_challenge` отдаются начиная с версии 20240529). `rooms/{room}` и
  `rooms/{room}/leaderboard` не имеют docblock'ов, хотя открыты для `public`.
- Seasons, Daily challenge, Team rankings отдельными разделами
  не документированы.

Следствие: перед реализацией рейтинга команд или Daily challenge нужен
короткий спайк на живом API и запись фактического ответа в карточку.
Недокументированное поле или параметр — явный риск, который фиксируем
в карточке, а не скрываем.

Детали из исходников:

- `RankingController@index` для API принимает только типы `charts`,
  `country`, `global` и `team`. Остальные отвечают 404.
- `SeasonsController@show` — HTML-представление (`ext_view`), маршрута в группе
  `api/v2` нет. В модели `Season` есть `name`, `finalised`, `ruleset_id`,
  дивизии и `UserSeasonScoreAggregate` (общий счёт), но наружу через API это
  не отдаётся.
- `Room::search` принимает `category` (`normal`, `spotlight`,
  `featured_artist`, `daily_challenge`), `season_id`, `mode`, `sort`,
  `type_group`, `limit`. `index`, `show`, `leaderboard` и `events` открыты
  для scope `public` без входа пользователя.

## Принятые решения (пользователь, 2026-10-03)

- **D1 → архив остаётся.** Spotlights — внизу стартового экрана неприметной
  строкой «Архив Spotlights» (opacity .8, без карточки). Текст и плашка
  на экране Spotlights сообщают, что поддержка прекращена (последний чарт —
  2020) и в osu! их заменили Seasons. Новых доработок Spotlights не делаем.
- **D2 → обе фичи обязательны, по очереди:**
  1. **P33 — рейтинг команд** во вкладке «Рейтинги». Вкладку стоит перестроить
     на внутренние вкладки (например, «Игроки / Команды / Страны»), а не
     добавлять ещё один переключатель к фильтрам. Перед кодом — проверка
     живого ответа `rankings/{mode}/team` (тип не описан в официальной
     документации).
  2. **P34 — Daily challenge («Карта дня»)** на стартовом экране (главная):
     карта, лидерборд дня; позже серии игрока в профиле. Перед кодом —
     проверка `GET /rooms?category=daily_challenge` с `x-api-version`.
- Варианты ниже — исходный разбор, сохранён для истории решения.

## Решения — исходный разбор вариантов

### D1. Что делать со Spotlights

- **A (рекомендую): убрать полностью.** Удалить карточку со стартового экрана,
  `lib/src/spotlights`, route `…/spotlights`, `openSpotlights`, allowlist
  `/spotlights` и `rankings/*/charts`, `ShareTarget.spotlight`, ARB-ключи
  `spotlights*` и тесты; обновить README, CHANGELOG и NAVIGATION_SPEC.
  Реализация остаётся в истории Git: коммиты до P31 и этот рабочий diff.
  Плюс: нет кода и строк ради данных 2020 года.
- **B: оставить скрытым архивом.** Уже работает, но поддерживается ради
  истории, а пользователь новых данных не увидит.

### D2. Что делать вместо Spotlights

- **A (рекомендую первым): рейтинг команд** (тип `team` не описан в официальной документации — см. выше) — переключатель «Игроки / Команды»
  во вкладке «Рейтинги». Официальный актуальный раздел, публичный API, а экран
  команды и флаги команд уже есть. Нужно уточнить формат ответа
  (`rankings/{mode}/team`: поля команды, очки, участники, пагинация) и
  добавить путь в public allowlist.
- **B (рекомендую вторым): Daily challenge** — карточка «Карта дня» на
  стартовом экране: карта, лидерборд дня, позже серии игрока в профиле.
  Самый «живой» контент. Сначала короткая проверка API: `category`,
  `x-api-version`, формат комнаты и лидерборда.
- **C: Seasons частично.** Комнаты сезона по известному id без общего
  рейтинга и дивизионов. Не похоже на страницу сайта и не держится
  без парсинга HTML. Не рекомендую.
- **D: рейтинг стран.** Простой и дешёвый, но мало кому интересный.

Предлагаемый порядок: D1-A → рейтинг команд → проверка Daily challenge →
Daily challenge → (по желанию) рейтинг стран.

### D3. Куда ставить Daily challenge (если делаем)

Стартовый экран, карточка «Сегодня»: это ежедневный контент, а не
постоянный рейтинг. Вкладка «Рейтинги» остаётся для постоянных таблиц
(игроки, команды, страны).

## Сетка карточек — исправлено

Замечание пользователя по скриншотам: в строке рейтинга флаги свисали ниже
аватара, а подпись «PP» висела посередине. В профиле иконка «прошлые ники»
стояла ниже имени, а ID оказывался под аватаром.

Правило (`lib/src/_shared/ui/avatar_bands.dart`, `OsuAvatarBands`): текст
рядом с аватаром занимает ровно его высоту. Верхняя полоса начинается
от верхнего края аватара, нижняя заканчивается на его нижнем крае.
Межстрочный запас над первой и под последней строкой обрезается
(`TextHeightBehavior`), чтобы с краями совпадали буквы, а не коробки строк.

- **Строка рейтинга** (`ranking_row.dart`): аватар 72 (`UiAvatar.row`).
  Сверху — позиция, ник и значение на общей baseline. Снизу — флаги
  и подпись «PP» по нижнему краю аватара. Цель 44 px у флага команды
  растёт вверх, видимый флаг стоит на нижней линии.
- **Профиль** (`player_card.dart`): аватар 96 (`UiAvatar.hero`). Сверху — ник
  и ID, снизу — флаги и статус. Иконка «прошлые ники» выровнена по верхней
  линии и правому краю контента; её 48 px цель выступает в отступ карточки
  и не сдвигает текст вниз.
- `OsuPlayerFlags(bottomAligned: true)` и `OsuTeamFlag.alignment` — для
  выравнивания по нижней линии. Прежнее центрирование (лидерборд карты)
  не менялось.
- Тест `test/src/_shared/ui/ranking_row_test.dart` проверяет верх значения,
  низ флагов, низ «PP» и низ видимого флага команды относительно аватара.
- Ограничение: при крупном шрифте текст не помещается в высоту аватара.
  Тогда колонка растёт, аватар остаётся сверху; узкий режим строки рейтинга
  не менялся.

## Плеер — переделан, нужна приёмка

`UiAudioPlayer` (`packages/tracksu_ui/lib/src/widgets/audio_player.dart`),
публичный API не менялся:

- **Капсула.** До запуска — только круглая кнопка 44 px на полупрозрачной
  подложке, обложка остаётся открытой. После запуска капсула плавно
  раскрывается (`AnimatedSize`; при reduce motion — без анимации): тонкий
  трек 4 px, ползунок 6 px, время «0:03 / 0:10» табличными цифрами.
- **Загрузка** — кольцо вокруг кнопки и бегущая полоса. **Ошибка** — иконка
  и причина из `AudioPlaybackFailure`.
- **Над обложкой** — матовое стекло (blur 18) только в активном состоянии.
  Без проигрывания blur не используется: в списках много обложек.
  **Внутри статьи** — та же капсула на `surfaceContainerHighest`.

Варианты на потом (не сделаны, нужен выбор):

1. **Мини-плеер внизу экрана**, пока трек играет и пользователь ушёл
   со страницы. Меняет принятое правило «уход со страницы останавливает
   звук» и требует новой навигационной политики.
2. **Waveform вместо трека.** Нужен анализ PCM; для iOS Vorbis он уже есть
   (WAV), для MP3 — только с декодером.
3. **Название трека в капсуле.** Над карточкой карты оно дублирует заголовок;
   полезно только во встроенном плеере статьи.

### Четвёртый круг правок (2026-10-03)

- **Единый «индикатор работы страницы»** (`_shared/ui/page_activity.dart`):
  `PageActivityHost` на странице собирает флаги занятости от независимых
  частей (`PageActivityReporter`), app bar показывает одну линию.
  `PageRefreshScope`/`PageRefreshTarget` дают pull-to-refresh скроллу, когда
  Bloc секции живёт глубже в его slivers.
- **Профиль, вкладки «Результаты» и «Карты»:** иконки обновления и блоки
  «Загрузка…» внутри списков убраны; тянем вниз — обновляется секция,
  прогресс — линия под app bar. Подгрузка страниц (load more) по-прежнему
  внизу списка.
- **Карта:** кнопка «Обновить результаты» и полосы прогресса в контенте
  убраны; pull-to-refresh обновляет карту и лидерборд, прогресс под app bar.
  Порядок: карточка карты → сложности → описание (с отступом) → лидерборд.
- **Переходы страниц:** явная `PageTransitionsTheme`: Android —
  `FadeForwardsPageTransitionsBuilder` (Material 3, плавный, учитывает

### Пятый круг правок (2026-10-03)

- **`OsuCategoryPicker<T>`** (`_shared/ui/category_picker.dart`) — общий
  компактный выбор категории с листом и группами. «Карты» и «Результаты»
  (лучшие / последние) используют его; чипы во вкладке результатов убраны.
- **Отсутствующие значения — мелким шрифтом.** `UiMetric(unavailable: true)`
  выводит пояснение (`bodyMedium`, secondary) вместо крупного числа:
  мировой/страновой рейтинг без места («Нет места»), время игры
  без данных, рейтинг в «Карте дня», PP результата без рейтинга (лист
  подробностей). В карточке результата `OsuPlayCard.performanceUnavailable`
  — «PP недоступны» мелким текстом вместо розового заголовка.
- **Пустые состояния списков тише:** `UiContentState.empty/offline` —
  иконка 24, текст `bodyMedium` secondary, отступ `lg`; ошибки остаются
  заметными (`titleMedium`).
- Сборка: Flutter 3.47 больше не реэкспортирует
  `CupertinoPageTransitionsBuilder` из material — импорт из cupertino.
