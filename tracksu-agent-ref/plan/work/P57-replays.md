# P57 — просмотр реплеев

2026-10-09 · пожелание пользователя. Статус: backlog (план).

## Что даёт API

- `GET /scores/{id}/download` (и legacy `{ruleset}/{id}`) — файл `.osr`,
  scope public, гостевой токен подходит, отдельный троттлинг
  `scores_download`. Только у результатов с `has_replay`.
- Файл карты: `https://osu.ppy.sh/osu/{beatmap_id}` (web-маршрут, текст
  `.osu`), аудио — нет в API (только preview 10 с).
- Счётчик просмотров реплеев: `replays_watched_counts` в профиле,
  `scores type=most_replayed`.

## Варианты

1. **«Скачать / открыть в osu!»** — кнопка на результате с `has_replay`:
   скачать `.osr`, отдать системному share/«Открыть в» (lazer на
   десктопе/планшете открывает реплей). Дёшево, честно.
2. **Свой 2D-просмотр (только osu!standard на старте):** парсинг `.osr`
   (LZMA-поток кадров курсора/клавиш), `.osu` (hit objects, тайминги),
   отрисовка поля: круги, слайдеры, курсор, judgement, таймлайн без звука
   или с preview. Большой объём (слайдер-кривые, моды HR/DT/EZ/HT,
   stack leniency), но это «фича, которой нет у других».
3. **Сторонний рендер (o!rdr и т. п.):** видео-рендер на чужом сервере —
   отдельные условия сервиса, приватность, лимиты; только по решению.

Рекомендация: 1 → затем 2 как отдельный проект с прототипом на одной карте.

## Риски

Троттлинг скачиваний (кэшировать файлы, не префетчить), права на
распространение карт/аудио (не хранить вне кэша), производительность
отрисовки на Android.
