# P07 — поэкранная интеграция и функциональная доработка

2026-09-07 · baseline `dfe33f2`, рабочее дерево чистое. Пользователь сообщил,
что механическая замена UI не является готовым продуктовым результатом.
Эта карточка — текущая очередь экранов, не второй план архитектуры.

## Что установлено по коду

- `guest/widgets/guest_shell.dart` открывает ProfileMain, панели вкладок нет.
  `app_router.dart` создаёт обычные push routes; OAuth success удаляет весь стек.
- Поиск — точный lookup `/users/{identifier}/{ruleset}`, не выдача результатов
  и не поиск карт. Search и профиль сейчас находятся на одной странице.
- Рейтинги работают через API, но UI — восемь mode/sort chips и ручной ввод
  кода страны. RankingEntryDto не читает avatar_url; карточка не показывает
  место в текущей таблице и выводит ranked_score даже в PP-режиме.
- В profile summary подписи уже содержат числа, которые повторяются в value;
  null global_rank попадает в label как #0. Это дефект, не финальное оформление.
- Scores и карты встроены последовательно в длинный профиль. Карты стоят
  перед scores; нет удобного раздельного просмотра/деталей результата.
- Media не завершено на уровне данных: profile cover/rank history,
  ranking avatar, beatmap covers и news first_image не доходят до UI.
- На исходном baseline новостной reader был text-only. Срез 2026-09-08 заменил
  его общим [ContentFrame](P07-rich-content.md) с отдельным ограниченным media
  loader; iframe/script по-прежнему не исполняются.
- UI kit содержит нужные композиции, но это не подтверждает доступность всех
  API-полей и не означает их интеграцию в сценарии приложения.

Срез может расширять DTO/domain/repository **вместе с потребителем**, когда
это нужно конкретной странице. Предыдущая формулировка «не смешивать с API»
не запрещает необходимое подключение её media/статистики; запрещён перенос
всех API-моделей заодно. DTO parsing остаётся в repository, raw payload — в source.

## Готовность каждой страницы

1. Сверены экран Stitch/старый сценарий/фактические API-поля; спорные функции
   помечены requires-data/future, а не изображены работающими кнопками.
2. Страница собрана из существующего public UI kit и app-level compositions,
   содержит реальные данные, фото или предсказуемый fallback.
3. Проверены по коду state/lifecycle: initial, content, empty, failure,
   refresh со старым контентом, load-more, retries/cancellation и Back.
4. Все тексты/числа/даты оформлены на семи языках; нет дублирования метрик,
   фиктивных #0, переносов логики/HTTP в widgets.
5. Format/analyze/build, короткий ручной checklist пользователя, отдельный
   локальный коммит и актуальный ROADMAP. Автотесты не добавляем/не запускаем.

«Raw migration выполнена» остаётся историческим фактом, но страницы получают
приёмку только по этим критериям. Не обещать завершить все срезы одним коммитом.
2026-09-07 пользователь подтвердил go_router + StatefulShellRoute с тремя
ветками и OAuth поверх shell; Android Back на корне вторичной вкладки
возвращает сохранённый Поиск. Прежний no-op повторного tap заменён 2026-09-08
на return-to-root активной вкладки; актуальный контракт в NAVIGATION_SPEC.
Backend и новые продуктовые политики этим решением не меняются.

## Checkpoint P07.2 — реализован, ручная проверка ожидается

Три ленивые stateful ветки, UiNavigationBar на деталях, сохранение стека при
переключении, системный Back из корня вторичной ветки к Поиску. Reselect теперь
возвращает root выбранной активной ветки, не уничтожая состояние её корня.
SearchHome теперь отдельная гостевая страница с ruleset, валидацией, кнопкой
и submit с клавиатуры; typed profile page не содержит поисковую форму.
OAuth поверх shell, callback вне route parameters, AccountActions реагирует
на status stream даже при cold callback. Android использует только app_links.
Новых partial-search/map-search endpoints в этом checkpoint нет; данные и
визуальную доработку профиля/результатов не считать выполненными.
Пункты 2–3 продолжены следующим checkpoint; этот раздел фиксирует только P07.2.

## Checkpoint P09 — реализован, ручная проверка ожидается

[Контракт и проверка профиля](P09-profile-product.md): exact lookup вынесен в
SearchHome, numeric ID/@username валидируются до запроса. В профиль подключены
cover.url, nullable play_time, level, grade_counts, дополнительные счётчики и
rank_history. Подписи не дублируют значения; null rank — без фиктивного #0.
Три ленивые вкладки сохраняют посещённые секции и прокрутку. Смена ruleset
сохраняет старый профиль, показывает загрузку, принимает только последний
ответ; повтор после ошибки запрашивает именно неудавшийся режим. Карты при
смене режима не перезагружаются. История без искусственных дат, с разрывами.

Из Stitch рассмотрен Player Profile (UI Kit, экран 341c473a51434763b6782328cd3ab3d2):
hero/метрики/группировка адаптированы к существующему UI kit и данным API.
Follow/PRO и декоративные изображения не перенесены как работающие функции.
Палитра и шрифты не менялись. Следом пункт 4: scores — компактное сравнение,
media и подробности; потом пункт 5 — карты. Их старая внутренняя композиция
не считается исправленной только благодаря новым вкладкам профиля.
