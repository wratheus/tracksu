# P07 / P09 — общий ContentFrame для пользовательского контента

2026-09-08 · **план следующего среза, не реализованный renderer**.
Baseline 5287774: SafeHtml + ProfileAboutSection отображают только безопасный
текст. Этот baseline намеренно удаляет изображения/стили и не сохраняет
интерактивность box/spoiler; полноценной поддержкой user page его не считать.

## Цель и первые потребители

Один переиспользуемый механизм богатого контента: профиль → новости → описание
карты при подключении соответствующей API-проекции. Он сохраняет содержание
и выразительность автора в мобильной теме, но не превращается в WebView.
Скрин пользователя: центрированный блок, цветные ссылки, жирные фрагменты,
раскрывающийся Collabs, изображение-счётчик и обычные абзацы снизу.

Источник формата: [официальный BBCode osu!](https://osu.ppy.sh/wiki/en/BBCode).
User pages используют BBCode. API page.html — готовое HTML-представление,
page.raw — исходник. Markdown не угадываем по символам: отдельный адаптер
появится только у настоящего Markdown consumer. BBCode/HTML не исполняемый код.

## Ответственности, без дублирования renderer в features

Предлагаемый поток:

```text
raw source → repository/DTO → общий normalizer → ContentDocument
                                                    ↓
                           ContentFrame.sliver / ContentFrame.body
                              ↓             ↓             ↓
                         rich text       media       disclosures
                              └────────── UI kit ──────────┘
```

- Source возвращает raw API payload как сейчас. Repository вызывает DTO и
  normalizer один раз на новую версию документа, не на каждый build.
- ContentDocument — immutable модель в shared/content/domain, без Flutter,
  HTTP/cookies/credentials: ID/версия, base URI, нормализованный контент,
  проверенные media/link descriptors и признаки неподдержанного содержимого.
- Normalizer в shared/content/data знает диалект osu! и проверенный allowlist.
  Распознаёт семантические конструкции **до удаления** исходных классов и стилей.
  Не копирует произвольные class/style/data-* в renderer. HTML не обрабатывается
  regex-заменами; DOM parser уже есть. Raw BBCode fallback — отдельный tokenizer
  с явной таблицей поддержанных тегов, не глобальные replace по вложенным тегам.
- ContentFrame живёт в shared/content/widgets, использует публичный tracksu_ui.
  У него нет знаний о ProfileBloc, NewsRepository или маршрутах приложения.
  Публичный контракт: document, localized labels, media policy/access,
  callbacks для ссылки/просмотра изображения. Имя и детали API фиксируются
  реализацией; новые пакеты/DI/controller без реального lifetime не вводить.
- Ui kit владеет оформлением text/link/media/quote/disclosure/notice и viewer
  frame. Domain не импортирует UI kit. Сетевые решения не прячем в контейнер.
- Уже используемый flutter_widget_from_html — кандидат для обычной разметки,
  custom builders — для наших media/disclosures. До выбора проверить, что
  renderer не запускает загрузку исходных src сам и что большой корневой div
  не превращает весь документ в один eagerly built блок. Если не обеспечивает
  нужные гарантии, нормализовать в блоки; собственный CSS/browser engine не писать.

## Контракт отображения

| Содержимое | Поведение в приложении |
| --- | --- |
| Абзацы, заголовки, bold/italic/underline/strike | Богатый текст, выделение/копирование, тема и системный text scale |
| Выравнивание, размер и цвет | Сохранять смысл оформления; размер ограничить шкалой UI kit, цвет — валидными значениями с проверкой контраста; не принимать произвольный CSS |
| URL и profile links | Сохранить подпись и ссылку; известные osu! profile/map URI можно передать typed router, остальные — внешнему обработчику; renderer сам не открывает URL |
| box/spoilerbox, inline spoiler | Нативное раскрытие, отдельное локальное состояние по стабильному ID; скрытый текст не читается screen reader до раскрытия |
| Цитаты/notice, списки, код | Общие оформленные блоки; code не интерпретируется как markup; длинная строка не расширяет весь экран |
| Таблицы | Только локальная горизонтальная прокрутка таблицы; bounded размеры/число ячеек, не общий sideways-scroll страницы |
| PNG/JPEG/WebP и другое разрешённое raster media | Ограниченное превью, сохранение пропорций, состояния loading/error/blocked, alt; тап открывает общий viewer с масштабированием |
| GIF/анимация | Первый кадр/явное действие; не запускать десятки анимаций автоматически, pause вне видимой области/при background |
| YouTube/audio/прочие embeds | Карточка с названием/доменом и действием открыть оригинал; без iframe/autoplay и фонового media prefetch |
| Imagemap/неподдержанные конструкции | Сохранить доступное содержимое и безопасные ссылки/fallback, не делать вид, что все click areas поддержаны |

Первый релиз компонента обязан закрыть screenshot-сценарий и обычные картинки,
box/spoiler, типографику и ссылки. Расширенные raw-BBCode теги/таблицы/imagemap
получают явный статус в compatibility matrix, не утверждение «поддерживает всё».

## Изображения и внешние запросы: решение до подключения

Вопрос отправлен пользователю. Предлагаемый default пока **не утверждён**:
проверенные osu!-хосты автоматически, остальные HTTPS media — по нажатию
«Загрузить внешние изображения» для текущего документа. Альтернатива — auto
для всех разрешённых публичных HTTPS media с явным disclosure в privacy.

- URL картинки/счётчика может раскрывать IP стороннему владельцу. Нельзя
  обещать отличить все tracking pixels по размеру, расширению или имени URL.
  Даже авто-загрузка разрешённого CDN не означает отсутствие серверных логов.
- Точный allowlist хостов, проверка каждого redirect, запрет credentials в URI,
  file/data/javascript, loopback/link-local/private endpoints. Суффикс домена
  не проверять наивным contains. Media loader не получает OAuth/session headers,
  cookies сайта, client secret или реферер с пользовательскими параметрами.
- Ограничивать байты загрузки, MIME/формат, redirects, время, concurrency и
  decoded dimensions. Resize/cacheWidth ограничивает декодирование, но сам по
  себе **не ограничивает скачиваемый файл**. SVG не разрешать как произвольный
  активный документ; решение по нему отдельно после проверки decoder.
- До разрешения media не запрашивать картинку, её размер, thumbnail, HEAD или
  favicon. В закрытом spoiler нет скрытой загрузки. Отказ не ломает текст.
- Кеш ограниченный; политика должна применяться и к cache hits. Постоянное
  «доверять всем сайтам», disk cache, proxy/BFF этим срезом не добавляются.

## Производительность и lifecycle

- sliver-конструктор в существующий CustomScrollView; body — только короткий
  контент в явно заданных ограничениях. Не shrinkWrap HTML со всеми картинками.
- Парсинг ограничен длиной/глубиной/числом узлов/медиа; сложный документ получает
  частичный fallback с оригиналом, не срывает загрузку профиля или всей новости.
- Ленивые блоки и media в видимой области, небольшая очередь загрузок с отменой;
  резервирование размеров уменьшает скачки scroll. Огромные внешние width/height
  и абсолютное позиционирование не управляют layout приложения.
- Раскрытие spoiler, progress/error картинки и viewer не перестраивают весь
  профиль/рейтинги и не делают повторный API request. Смена document ID
  обнуляет локальные разрешения/selection/раскрытия; уход закрывает owned resources.
- Live theme/locale/text scale и Back/закрытие viewer согласованы с shell.

## Последовательность коммитов и приёмка

1. Контракт/compatibility matrix на примерах актуального osu! HTML, общий
   ContentDocument/normalizer, сохранение текстовых потребителей.
2. Общий ContentFrame: стиль, ссылки, disclosures и каталог состояний; профиль
   и новости на одном owner, удалить прежние ad hoc wrappers после переключения.
3. Media loader + выбранная privacy policy + viewer, изображения и limits.
   Политика не расширяется при переходе из профиля в новости.
4. Подключение к описаниям карт с их data projection; rich content считается
   готовым по матрице, не по факту появления frame-класса.

Проверки: format/analyze/main/catalog debug, ручной device checklist пользователя.
Автотесты по-прежнему отложены. Проверить mixed formatting, Collabs с картинками,
длинный текст/таблицу/URL, отсутствующий/битый HTML, oversized media, офлайн,
отказ загрузки, закрытый spoiler, смену документа, light/dark, CJK/text scale,
viewer Back и сохранение основного scroll. Скрин счётчика не использовать для
реальных автоматических внешних запросов в процессе разработки.

Откат — адресные revert без миграции аккаунтов/токенов. Privacy-политика,
поддержанные конструкции и ещё не реализованные функции документируются явно.
