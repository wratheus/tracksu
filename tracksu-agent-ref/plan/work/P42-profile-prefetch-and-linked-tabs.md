# P42 — профиль: предзагрузка разделов и свайпер, связанный со страницей

2026-10-05 · implemented in code / awaiting_manual_check.

## Замечания пользователя

1. «Медленные загрузки в профиле во время переключения вкладок — лучше
   делать запросы заранее и кэшировать при заходе в профиль асинхронно».
2. «Свайпер связывать со страницей: сейчас он доезжает после реального
   свайпа».

## 1. Предзагрузка разделов профиля

**Было.** `TabBarView` строит вкладку только при первом показе, а Bloc
«Результатов» и «Карт» создавался внутри вкладки (`ProfileScoresMain`,
`ProfileBeatmapsMain`). Запрос уходил только после перехода на вкладку —
пользователь всегда ждал полный сетевой цикл.

**Стало (архитектура).**
- Владельцы Bloc вынесены над вкладками: `ProfileScoresProvider`
  (ключ — игрок + режим) и `ProfileBeatmapsProvider` (ключ — игрок),
  `BlocProvider(lazy: false)`. Они создаются вместе с загруженным
  профилем, и первые страницы (лучшие результаты и «Часто играемые»)
  запрашиваются **параллельно**, пока читается «Обзор».
- Виджеты разделов (`ProfileScoresSection`, `ProfileBeatmapsSection`)
  по-прежнему строятся лениво и с keep-alive — сохраняются прокрутка и
  выбранная категория.
- Смена режима пересоздаёт только провайдер результатов (новый ключ) и
  сразу запрашивает новый режим в фоне.
- Кэш: оба Bloc уже пишут первую страницу каждой категории в сессионный
  `PageCache` (30 мин, 40 записей). Повторный вход в тот же профиль
  показывает данные сразу и перепроверяет их по сети.
- Цена: +2 запроса на открытие профиля (они и так нужны при переходе на
  вкладку). Остальные категории (недавние, первые места, любимые карты…)
  **не** предзагружаются, чтобы не делать 10+ запросов на каждый профиль;
  при выборе категории — один запрос, повторный выбор — из кэша.

Возможное развитие (не сделано): предзагрузка следующей по популярности
категории по простою (после первой страницы) и общий `ProfileSession`
с отменой всех запросов при уходе со страницы.

## 2. Свайпер, связанный со страницей

**Было.** Сегментный контрол получал только `selected = controller.index`,
а `TabController.index` меняется, когда страница уже доехала. Поэтому
бегунок трогался после свайпа.

**Стало.** `UiSegmentedControl.position` — непрерывный индекс страницы
(`TabController.animation`). Контрол слушает его и, как только страница
проходит половину, **переключает** бегунок на соседний сегмент той же
анимацией, что и при тапе (уточнение пользователя: «должно просто
включаться, как сделано сейчас» — без плавного следования за пальцем).
Перестройка — только при смене ближайшего сегмента. Тап → `animateTo`.
Подключено в профиле и «О приложении».

## Проверить

- Открыть профиль, подождать 1–2 с на «Обзоре», перейти в «Результаты» и
  «Карты» — данные уже есть, без скелета.
- Сменить режим на «Обзоре» → «Результаты» нового режима готовы.
- Тянуть страницу профиля пальцем: на середине свайпа бегунок
  переключается на следующую вкладку; вернуть страницу — бегунок
  переключается обратно.
