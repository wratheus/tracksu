# P05.1 — DI and bootstrap

Статус: `awaiting_manual_check` · 2026-09-04.

## Реализация

- `main` создаёт Flutter binding один раз и запускает `BootstrapApp`.
- `BootstrapApp` единожды вызывает `registerDependencies()`, показывает loading,
  а при неудаче предоставляет retry без параллельных попыток.
- `DepsContainer` содержит единственную реальную shared dependency этого шага —
  `TracksuAppRouter`; `DepsScope` передаёт неизменный контейнер вниз дерева.
- `AppMain` — единственный текущий consumer: собирает `MaterialApp` из router.
  Стартовый экран остаётся legacy `LoginPageWidget`; HTTP, storage, analytics,
  repositories и Bloc сюда намеренно не добавлены.

## Ownership

| Объект | Создаёт | Владелец | Закрытие |
| --- | --- | --- | --- |
| `TracksuAppRouter` | `registerDependencies` | `DepsContainer` | Не владеет ресурсами |
| `DepsContainer` | bootstrap | `BootstrapApp` | Не владеет ресурсами на этом шаге |

## Проверка

- `fvm dart format` новых DI/bootstrap файлов — успешно.
- Scoped `fvm dart analyze lib/main.dart lib/src/app lib/src/_core` — без issues.
- Автотесты не запускались.

Ручная проверка: cold start показывает прежний login screen без повторного
bootstrap; при будущей ошибке и retry не создаются параллельные контейнеры.
