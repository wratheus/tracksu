# Будущие продуктовые идеи Tracksu

2026-09-08 · пожелания пользователя, **deferred**, не текущая реализация.
Этот список не обещает доступность API и не разрешает запуск backend/SDK.

## После основной клиентской доработки

- Друзья своего аккаунта: чтение, поиск/список, переход в профиль; friends.read
  и re-consent отдельно. Приватный cache только в своём session scope,
  очистка на logout/account switch. Нет списка друзей чужого профиля.
- Чаты: сначала проверить реально доступные osu! OAuth scopes и ограничения
  сторонних клиентов. Не обещать полноценный мессенджер по наличию API routes.
  Затем отдельные контракты сообщений/состояний, moderation и приватности.
- Push: определить события, источник/server delivery, opt-in, настройки,
  отключение/отвязку устройства и deep links. Не путать локальные уведомления
  и серверный push; Firebase/стоимость/политика согласуются отдельно.
- Аналитика действий приложения остаётся существующей P06.1, не дублируем её.
  Продуктовая аналитика игровых показателей — другой feature.
- Сравнение игроков: одинаковые ruleset и scoring policy, timestamps freshness,
  сравнимые PP/accuracy/ranks/scores, отсутствие данных без подставных нулей.
- «Полная поддержка» — отдельная матрица функций и доступности API: профили,
  карты/сложности, результаты/mods, рейтинги, новости, социальные сценарии;
  не неограниченное обещание полного клона osu! или игрового клиента.

## Если продукт востребован: развитие BFF

Основа P17 — server OAuth callback и хранение secret на сервере. После решения
о спросе/бюджете можно расширять в послойный backend: domain/use cases,
repositories/infrastructure, API contracts и отдельные фоновые задачи.
Стек, hosting, права на данные, хранение, стоимость и сроки пока не выбраны.

Кандидаты в ключевые функции:

1. Нейроанализ профиля: сильные/слабые стороны на основе доступных scores,
   объяснение с привязкой к данным и явной неопределённостью.
2. Рекомендации карт для улучшения/фарма: ruleset, история, предпочтения,
   актуальность difficulty/PP; рекомендации не гарантируют результат.
3. Сравнение двух игроков с объяснением различий, без выдуманных причин.
4. «Примерка» PP-score: what-if влияние гипотетического результата на профиль.
   Числа рассчитывает воспроизводимый версионированный алгоритм с учётом
   weighting/bonus/повторов и scoring policy, не языковая модель. Результат —
   оценка по известному набору данных, не гарантированный будущий rank/PP.

Обязательные входные условия: API limits/caching и права osu!, data inventory,
privacy/consent перед передачей данных AI-провайдеру, минимизация/сроки хранения,
защита токенов, пользовательское удаление, rate/cost limits. Не строить массовый
скрейпинг профилей и не выводить чувствительные характеристики игроков.
Функции не включаются автоматически вместе с текущим UI/рефакторингом.
