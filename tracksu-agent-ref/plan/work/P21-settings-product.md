## Результат

Цельный экран настроек: аккаунт, язык, тема, внешние изображения. Используем
существующие UiSurface/UiTile/UiModal/UiAvatar, палитру не меняем. Общий выбор
языка с флагами и текущим значением доступен из настроек и верхнего меню.
Выход в обоих местах проходит одно подтверждение. Защищаем повторные переходы.

Тема system/light/dark сохраняется локально существующим secure storage,
восстанавливается до MaterialApp. Смена темы не пересоздаёт router/DI/стек.
Новых dependencies, API, analytics или текстов юридических обещаний нет.
Privacy/terms остаются отдельным согласованием P01.3, не фиктивной ссылкой.

Storage владеет записью, ThemeController — выбором/restore, settings — UI,
общие language picker и sign-out action переиспользуются из account menu.
Новые подписи — семь ARB с descriptions в английском шаблоне.

Gate: gen-l10n, scoped format, analyze lib/packages, diff review.
Без тестов/APK по решению пользователя. Ручная приёмка: guest/auth, отмена
выхода, повторные нажатия, все темы/языки и сохранение после перезапуска,
длинные подписи и media allow/deny. Откат — revert коммита; новый theme key
безопасно игнорируется старым кодом, прочие данные не удаляются.

## Реализовано

- SettingsMain → SettingsScreen; экран собран из существующих UiSection,
  UiSurface, UiTile и общих модалок. Нет собственного набора цветов/текстовых стилей.
- ThemeStore хранит `app_theme_mode`; ThemeController принадлежит DepsContainer,
  восстанавливается до AppMain, закрывается с контейнером. System — исходное
  поведение, неизвестная/нечитаемая запись не блокирует запуск. Ошибка записи
  не меняет текущую тему; параллельная запись не запускается.

  выход остаётся локальным, запросов revoke/удаления аккаунта не добавляли.
