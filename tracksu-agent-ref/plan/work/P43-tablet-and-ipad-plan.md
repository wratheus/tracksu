# P43 — адаптация под планшеты и iPad (план на будущее)

2026-10-05 · backlog (оценка по запросу пользователя, кода нет).

## Где мы сейчас

- iOS-таргет уже собирается для iPhone **и** iPad
  (`TARGETED_DEVICE_FAMILY = "1,2"`), ориентации iPad — все четыре;
  Android без ограничений размера окна. То есть приложение на планшете
  **запускается**, но это растянутый телефонный интерфейс: одна колонка
  на всю ширину, карточки по 1200+ px, нижняя навигация.
- Плюсы архитектуры: весь UI собран из компонентов `tracksu_ui` и
  sliver-списков; ширину уже учитывают строка рейтинга (узкий режим),
  сетка метрик (колонки по ширине), лист «Поделиться», грейды
  (≤ 320 px), картинки статей. Глобальных брейкпоинтов и ограничения
  ширины контента нет.

**Вывод:** сложность средняя. Базовая «нормальная» версия для планшетов —
примерно 1–1,5 недели; полноценный master-detail — ещё 1–2 недели.

## Важное до релиза

Пока в таргете есть iPad, App Store потребует скриншоты iPad 13" и
проверит приложение на iPad. Варианты: (а) сделать этапы 1–2 ниже до
релиза; (б) временно выпустить только для iPhone (`TARGETED_DEVICE_FAMILY
= 1`) — iPad будет запускать iPhone-версию в окне совместимости.
Решение — за пользователем.

## Этапы

### Этап 1 — основа (S, 1–2 дня)
- Брейкпоинты по Material 3 window size classes: compact < 600,
  medium 600–839, expanded 840–1199, large ≥ 1200 (`UiWindowSize`
  через `MediaQuery.sizeOf` в tracksu_ui).
- Ограничение ширины контента: чтение (статьи, «О приложении»,
  настройки) ≤ 720 px, списки ≤ 1040 px, по центру
  (`SliverConstrainedCrossAxis`/`SliverPadding` в общих обёртках, чтобы
  не трогать каждый экран).
- Модальные листы на широких экранах — диалог/лист ограниченной ширины
  (`UiModal`).

### Этап 2 — навигация и сетки (M, 3–5 дней)
- `GuestShell`: нижняя `NavigationBar` → `NavigationRail` на medium+
  (те же ветки `StatefulShellRoute`, повторный тап = наверх).
- `UiSliverCardList` → адаптивная сетка: 2 колонки на medium, 3 на
  expanded для карточек карт, новостей, результатов, команд/стран.
- Профиль: «Обзор» в две колонки (шапка + метрики | графики/история).
- Карта: обложка/сложности слева, рейтинг/комментарии справа на expanded.
- Видео и плееры: ограничить ширину, полный экран без изменений.

### Этап 3 — master-detail (L, 1–2 недели, по желанию)
- Новости: список слева, статья справа; рейтинги: список + профиль.
- Нужен второй навигатор в панели и правила Back/deep links/restoration
  (`NAVIGATION_SPEC`), это главная архитектурная работа.

### Этап 4 — ввод и многозадачность (S–M)
- iPad Split View / Slide Over, Android freeform и складные устройства:
  корректная перестройка при изменении размера, без пересоздания Bloc.
- Указатель: hover-состояния, скролл трекпадом/мышью, клавиатура
  (Tab-фокус, Esc закрывает листы, ⌘F — поиск).

## Риски
- `BackdropFilter` (стекло сегментов, плеер) на больших площадях —
  проверить производительность на iPad.
- Крупный шрифт + 3 колонки — нужны минимальные ширины карточек.
- Скриншоты стора и QA на iPad mini, iPad Pro 13", Android 10" и
  складном устройстве; добавить размеры в каталог UI.
