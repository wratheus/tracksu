# P00.1 — inventory identity, signing и baseline

Статус: `in_progress` · 2026-09-04.

## Цель

Зафиксировать безопасный исходный baseline для миграции: identity приложения,
наличие signing materials, старой сборки и локальных данных, а также состояние
store/OAuth. Не читать, не копировать и не записывать секреты.

## В scope

- Read-only audit tracked Android/iOS/native config, pubspec, Git history и
  безопасного наличия файлов signing artifacts.
- Факты, которые может проверить только владелец в Play Console, Apple Developer/
  App Store Connect и osu! settings.
- Карта неизвестного и порядок его закрытия.

## За рамками

- Смена application ID, Bundle ID, store/developer account, OAuth registration,
  credentials или подписи.
- Создание/экспорт ключей, сборка/release, Flutter/Gradle upgrade и любые
  изменения app-кода или native host.
- Автотесты, публикация, обращения в поддержку и ротация secret.

## Решения владельца от 2026-09-04

| Вопрос | Решение / состояние | Последствие |
| --- | --- | --- |
| Android developer account | Создаём новый аккаунт разработчика | Не планируем публикацию через старый удалённый аккаунт; создание аккаунта — действие владельца, не этой задачи |
| Старые Android signing keys | Потеряны | Обновление старой установки не является целевым путём, пока отдельно не доказано обратное |
| Новый Android application ID | Ещё не выбран | Текущий `com.sgoollreps.tracksu` сохраняем только как исторический baseline; не меняем его до P01.1 |
| iOS | Legacy host удалить | Владелец явно подтвердил удаление tracked `ios/`; P04 остаётся отдельной будущей задачей нового shell |

Если доступ к старой Play Console неожиданно сохранился и там включён Play App
Signing, Google позволяет reset **upload key** через Console; это не равно
восстановлению developer account и не меняет app-signing key. Мы не начинаем
этот путь без отдельного решения. Официальная инструкция:
[Use Play app signing](https://support.google.com/googleplay/android-developer/answer/9842756).

### Подтверждение статуса старого Play account

Скриншот владельца от 2026-09-04 из Play Console подтверждает: developer profile
SgoollReps и все его приложения удалены; в интерфейсе явно сказано, что изменения
в приложениях или store listings опубликованы не будут. Tracksu отображается как
удалённое приложение с `com.sgoollreps.tracksu`. Это достаточное основание не
планировать новый release из этого account. Не предполагаем, что новый account
сможет опубликовать update с тем же application ID: новый product release получает
новый ID после P01.1.

## Целевой путь Android (предварительно)

Новый аккаунт и потерянные keys означают новый signing lineage. После P01.1
будут выбраны product/developer name, контролируемый reverse-domain prefix и
новый application ID; затем P03 создаст новый keystore в защищённом месте и
две независимые резервные копии. Не генерируем key и не регистрируем аккаунт
до выбора package ID и отдельного подтверждения владельца.

Новая установка не получает автоматически старые secure-storage/preferences.
В P08 явно решим, какой onboarding, re-login и допустимый перенос данных
возможны. Старую Android identity/историю не удаляем ради нового пути.

## План небольших checkpoint'ов

1. `docs(p00): record repository identity baseline` — эта карточка, дорожная
   карта, перенос документации в repo и удаление legacy `ios/`. Без Android
   кода/секретов; Git commit служит recovery point для iOS host.
2. `docs(p00): record owner-verified store and signing inventory` — после
   ответов пользователя: только факт/дата/неизвестное, без private values.
3. `docs(p00): define migration preservation baseline` — карта сохранения,
   recovery и список блокирующих решений; затем P00 переводится в
   `awaiting_manual_check` или дробится дальше.

Коммиты не созданы; staging адресный, без `git add .`.

## Что нужно от владельца

Не присылай ключи, пароли, сертификаты, access/refresh tokens или OAuth secret.
Достаточно ответить фактами/скриншотами без чувствительных значений:

1. **P01.1 naming:** выбрать новый product/developer name и контролируемый
   reverse-domain prefix. Тогда можно выбрать `com.<owner>.<product>` без
   случайного временного ID.
2. **osu!:** есть ли доступ к владельцу OAuth app/settings; известны ли текущие
   redirect URI и scopes. Secret не нужен и не присылается.
3. **Данные/цель:** есть ли устройство со старой установкой; нужна ли ей только
   историческая проверка или какой-то перенос в новый продукт. Android остаётся
   целевой платформой; iOS зависит от решения выше.
